# AstraCode

AI chat + Code mode. Mobile-first (PWA).

- **Backend:** Cloudflare Worker + D1 (database) + R2 (payment slips, generated images, backups) + Cron Trigger
- **Frontend:** files in `public/`. Served by the Worker itself, or by Vercel.

## 1. Cloudflare (always needed)

### Database

New database: run `schema.sql`.

Existing database: run the migrations you haven't run yet, in order, in the D1 Console:

1. `migrate-1.sql`
2. `migrate-2.sql`
3. `migrate-3.sql`
4. `migrate-4.sql`
5. `migrate-5.sql`
6. `migrate-6.sql` (wallet, coupons, API keys, 2FA, memory, folders, file history, tickets, blog, audit log)
7. `migrate-7.sql` (Slip2Go, API key budgets)

If a migration fails with "duplicate column", it was already run. Skip to the next one.

### Worker

**Option A: dashboard.** Paste `dist/worker.js` into Edit code. To rebuild it, run `node build-single.mjs`.

**Option B: terminal.** Run `wrangler deploy`.

### Bindings

| Type | Variable name | Points to |
|---|---|---|
| D1 | `DB` | the `astracode` database |
| R2 | `SLIPS` | the `astracode-slips` bucket |
| Cron Trigger | — | `0 * * * *` (every hour). Settings → Triggers → Cron Triggers. Renews plans from Wallet, sends expiry reminders, cost alerts, daily backup at 03:00 Bangkok time, cleanup. |

### Variables and Secrets

| Name | Type | Purpose |
|---|---|---|
| `ADMIN_EMAIL` | Text | This email becomes admin on sign-up (only if no admin exists yet) |
| `DEEPSEEK_KEY`, `ANTHROPIC_KEY`, … | Secret | AI provider API keys |
| `SECRET_KEY` | Secret | Encrypts users' GitHub tokens. Use any long random string. Never change it after use. |
| `PROXY_SECRET` | Secret | Must equal the one on Vercel. Only needed when using Vercel. |
| `SLIP_API_KEY` | Secret | byshop slip check (optional) |
| `SLIP2GO_KEY` | Secret | Slip2Go Secret Key. Set the API URL and receiver account in Admin → Settings. Set Slip2Go's IP whitelist to `*`. |
| `PUBLIC_URL` | Text | Your main domain, e.g. `https://astracode.panderx.xyz`. Used in email links and OAuth callbacks. |
| `RESEND_KEY` | Secret | Email (verify, reset password, receipts, reminders). Also set sender in Admin → Settings. |
| `TAVILY_KEY` | Secret | Web search in chat |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | Secret | Google login. Redirect URI: `<PUBLIC_URL>/api/oauth/google/callback` |
| `LINE_CHANNEL_ID`, `LINE_CHANNEL_SECRET` | Secret | LINE Login. Callback URL: `<PUBLIC_URL>/api/oauth/line/callback`. Enable the email permission to link accounts by email. |
| `LINE_ALERT_TOKEN` | Secret | LINE Messaging API channel access token for admin alerts (LINE Notify was shut down). Set the target ID in Admin → System. |
| `OPENAI_KEY` | Secret | Image generation (name configurable in Admin → Settings) |

`SECRET_KEY` is now also used for 2FA secrets. Changing it disables everyone's 2FA and GitHub link.

## 2. Vercel (optional, e.g. `astracode.panderx.xyz`)

Vercel serves `public/`. The Edge Function `api/proxy.js` forwards every `/api/*` request to the Worker.

Because of this, cookies, streaming and rate limits work normally on your own domain.

1. Import the whole project. `vercel.json` already sets the output directory, clean URLs and security headers.
2. `vercel.json` also forwards `/v1/*`, `/robots.txt`, `/sitemap.xml` and `/blog/<slug>` to the Worker.
3. In Settings → Environment Variables, add:
   - `WORKER_URL` = `https://astracode.xxx.workers.dev`
   - `PROXY_SECRET` = the same value as on the Worker
4. Deploy, then add the domain in Settings → Domains.

### Limits on Vercel

- Max request body is 4.5MB. File and image attachments sent to the AI must fit within this.
- If you change the CSP in `src/worker.js`, change it in `vercel.json` too.

## GitHub (Code mode)

Users connect GitHub with a fine-grained Personal Access Token that has the **Contents: Read and write** permission.

### Supported actions

- Clone a repo into a new project
- Fetch (status)
- Pull: per-file 3-way merge. When a file was changed on both sides, the user chooses which version to keep.
- Commit & Push

### How it works

- Binary files and files over 500KB in the repo are skipped. They stay on GitHub untouched.
- Each GitHub action uses at most 5 subrequests, so it fits the Workers Free plan.
