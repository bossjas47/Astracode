# AstraCode

AI chat + Code mode. Mobile-first (PWA).

- **Backend:** Cloudflare Worker + D1 (database) + R2 (payment slips, generated images, backups) + Cron Trigger
- **Frontend:** files in `public/`. Served by the Worker itself, or by Vercel.

### Limits (like Claude)
Usage is metered in **real cost (baht)** from each model's cost prices (Admin → models), shown to users as %. Two limits per plan, both editable in Admin → plans: a 4-hour window that starts at the user's first message, and a weekly window that starts at the first use of the week and resets 7 days later. A model's `cap_pct` limits it to that share of the weekly budget (e.g. Opus 50). Chat, Code and autocomplete share one pool. When the limit is full the user can overflow to the Wallet at sell prices. Worst-case monthly cost of a plan = weekly budget × 4.33 (shown in the plans list).

If a migration fails with "duplicate column", it was already run. Skip to the next one.

## Firebase (login)

Sign-up, login, Google login, email verification and password reset use Firebase Auth. The Worker only checks the Firebase ID token and then makes its own session cookie.

In the Firebase console (project `astra-892a8`):

1. Authentication → Sign-in method: enable **Email/Password**.
2. Authentication → Templates: set the language to Thai.
3. Admin → Settings → "ล็อกอิน": the Firebase Web API key (default is the astra-892a8 key). If the key has HTTP-referrer restrictions in Google Cloud, allow `astracode.panderx.xyz/*`; the Worker sends that Referer.

The Worker calls the Firebase Auth REST API itself (`/api/auth`), so the browser never talks to Google; a blocked network, CSP or ad blocker cannot break login.

Google login uses the Worker's own OAuth (`/api/oauth/google`): Google Cloud → APIs & Services → Credentials → OAuth client (Web), add the redirect URI `https://astracode.panderx.xyz/api/oauth/google/callback`, then paste the Client ID and Client Secret in Admin → Settings → "ล็อกอิน" (or set Worker secrets `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET`).

Users must verify their email before the first login. An existing account (from before Firebase) links automatically when the user signs up or logs in with Google using the same email. LINE login still uses its own OAuth (Firebase has no LINE provider).


## 2. Vercel (optional, e.g. `astracode.panderx.xyz`)

Vercel serves `public/`. The Edge Function `api/proxy.js` forwards every `/api/*` request to the Worker.

Because of this, cookies, streaming and rate limits work normally on your own domain.

1. Import the whole project. `vercel.json` already sets the output directory, clean URLs and security headers.
2. `vercel.json` also forwards `/v1/*`, `/robots.txt`, `/sitemap.xml` and `/blog/<slug>` to the Worker.
3. In Settings → Environment Variables, add:
   - `WORKER_URL` = `https://astracode.xxx.workers.dev`
   - `PROXY_SECRET` = the same value as on the Worker
4. Deploy, then add the domain in Settings → Domains.

### Limits on Vercel

- Max request body is 4.5MB. File and image attachments sent to the AI must fit within this.
- If you change the CSP in `src/worker.js`, change it in `vercel.json` too.

## GitHub (Code mode)

Users connect GitHub with a fine-grained Personal Access Token that has the **Contents: Read and write** permission.

### Supported actions

- Clone a repo into a new project
- Fetch (status)
- Pull: per-file 3-way merge. When a file was changed on both sides, the user chooses which version to keep.
- Commit & Push

### How it works

- Binary files and files over 500KB in the repo are skipped. They stay on GitHub untouched.
- Each GitHub action uses at most 5 subrequests, so it fits the Workers Free plan.

## Terminal (Code mode)

The Code page has a Terminal tab, and the AI can write `RUN <command>` to run commands. Commands run in the user's browser with [almostnode](https://github.com/macaly/almostnode) (MIT), inside `/node-runner` (a sandboxed iframe on a separate origin, so it cannot use the user's session). It supports `npm install`, `npm test`, `npm run`, `node file.js`, CLIs in `node_modules/.bin`, `ls`, `cat`, `echo`. It does not support git, python, `node -e`, or native addons. Files a command creates or changes (except `node_modules`) are saved back to the project.

It downloads packages from `registry.npmjs.org` and esbuild-wasm from `esm.sh` and `unpkg.com` in the user's browser. Nothing runs on your server.

Rebuild `public/node-runner.js`: `npm i almostnode pako` then `npx esbuild tools/node-runner-entry.js --bundle --minify --format=iife --platform=browser --target=es2022 --alias:node:zlib=./tools/zlib-shim.js --outfile=public/node-runner.js`.

### Claude's own code execution tool (not used)

The Claude API has a built-in code execution tool. It runs Python 3.11 and Bash on Anthropic's servers, has no internet (so no `npm install`), and has 1,550 free hours a month per organization, then $0.05 per container-hour. It only works with Claude. AstraCode does not use it: the `RUN` terminal above works with every model. See the comment above `callModel` in `src/worker.js` if you want to add it for Python/data tasks.
